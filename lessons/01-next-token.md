# 模型只做一件事：猜下一个 token

读完这一课，你应该能讲清两件事：模型生成一句话时，每一步在算什么；你下载的 9B 模型里，那 90 亿个数字是什么。

先不要管 LoRA、loss、显卡。那些是后面几课的事。这一课只建立一个画面。

## 它和你平时写的 if 不一样

你如果用手写分析程序，会写成这样：

```text
如果词典里没有「张三」：
    结论写成「缺词」
```

大模型里面没有这行 if。它是一个很大的计算：给你已经写好的上文，算出下一个碎片有多可能。这个碎片叫 token，下一课再细讲。现在先把它想成「下一个字或下一个词的一块」。

生成是一轮一轮重复的：

1. 读入目前为止的全部上文。
2. 给词表里每一个可能的下一块算一个概率。概率高的，是它觉得更像会接在这里的字。
3. 挑出一块，接到末尾。
4. 回到第 1 步，直到写完，或者写到长度上限。

用「打电话给张三」这条样本想一次。上文已经有系统提示和问题单。模型先猜结论的第一个字。在金标里，这个字是「#」，因为结论以 `## 口径` 开头。它写下「#」之后，再猜下一个，金标是另一个「#」。再下一个是「口」。一句结论就是这样一点点接出来的。

所以模型「回答问题」的时候，并不是在脑子里先想好整段话再吐出来。它每次只决定紧接着的那一小块。

## 参数就是那一堆数字

每次算概率，都要用到一大组数字。这些数字叫参数，也叫权重。`Qwen3.5-9B` 里大约有 90 亿个。9B 的 B 是 billion，十亿。模型文件很大，就是因为要把这 90 亿个数字存下来。

这 90 亿个数字在你下载之前已经被训练过了。训练的意思是：拿大量文本，让它猜下一个字，猜错了就稍微改一改这些数字，改到猜得更准。见过的中文、泰语、德语、阿拉伯语、Python 越多，这些语言的下一块就越猜得像样。

你们厂里的规程它没见过。比如「没有声学 dump，就不能写音素已经验证」。这句话不会自动出现在那 90 亿个数字里。你后来做的微调，就是用分析员写好的标准答案，把猜测往这种写法上推一推。第 3 课和第 5 课讲具体怎么推。这里先记住：你是在一个已经会写字的模型上做小幅调整，不是从零造一个模型。

## 上文从哪里来

模型自己没有「当前这张问题单」的记忆。每次调用，都要把上文重新交给它。在这个仓库里，上文按顺序是：

1. `prompts/system.md`：岗位说明。告诉它自己是问题单分析员，必须先写脚本，再按证据写五个标题。
2. 用户消息：这张单的 JSON，比如车厂、语种、标注、REC。
3. 它自己写出来的脚本。
4. 沙箱跑完脚本之后打印的 JSON。
5. 然后它才继续写结论。

第 1、2、4 段是别人准备好的。第 3、5 段才是你希望它学会写的。这个差别到第 4 课会变成 loss 的开关。现在先知道：系统提示改了，它后面的猜测就会跟着变。所以 `prompts/system.md` 不是给人看的说明书，它是每次都喂进模型的第一段上文。

## 这一课你动手做的事

打开 `prompts/system.md`。不要一次读完八课。读完这份提示，在纸上写三行：

- 它被要求先做什么（写脚本，还是直接下结论）
- 结论必须用哪几个标题
- 什么样的证据它不能写成已经核实

写完再进入第 2 课。第 2 课解释「下一块」到底是怎么切的，以及为什么一条问题单不能无限长。
