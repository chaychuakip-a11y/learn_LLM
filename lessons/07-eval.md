# 背答案、验证集，和 loss 曲线

读完这一课，你应该能分开两件事：loss 下降说明什么，以及还要再看什么，才能说这个模型会分析新的问题单。

## 训练 loss 下降，表示金标变得更好猜

蓝线是训练 loss。它下降，表示 `[要学]` 的那些 token，也就是脚本和结论，模型给正确 token 的概率变高了。写法更像你的金标了。

这是好事，也只是这件事。它不表示：

- 车端引擎变得更准
- 新的泰语 POI 单一定能分析对
- 正式门禁可以通过

它只表示：在它正在看的这些训练单上，接下一字更顺了。

## 背答案是什么样

练习册只有几条，又反复看很多遍，模型可以记住「看到示例车厂 D、张三，就写那一段结论」。换一个车厂、换一个名字，它仍把旧句子套上去。训练 loss 会很低，因为旧题它已经会了。这就是背答案。

样本只有几十条时，把 `NUM_TRAIN_EPOCHS` 从 3 改成 20，多半是在加深这种记忆。要加的是新单，而且类型要散开：

- 联系人，按槽准，词不在词典里
- 导航或 POI，词在词典里，WFST 路径却走不通
- 正确文本出现在某个分支里，但输给了别的分支
- 云端结果，没有分支分数，也没有声学 dump

这四种最好不要全挤在同一种语言里。你的四条教学样本就是按这个思路编的。真实数据也按这个思路去补，而不是把同一张单复制二十遍。

## 验证集是训练时不许用来改权重的单

验证集的样本模型可以看，用来算一个 loss，但这个 loss 不拿去更新 LoRA。这样你才能观察到：它在没被拿来改权重的单上，还接不接得上。

留验证集要按车厂和语种留。比如泰语的单里留出一部分永远不进训练集。如果验证集和训练集是同一张单，橙线只是蓝线的回声。

当前示例的验证集只有 `ar_media_003` 一条。它的作用是让训练脚本的验证步骤能跑通。橙线下降或上升，都不能用来宣布多语种已经学会。真实项目里，每个主要语种都要有留出的单。

## eval loss 仍然是在对答案

验证 loss 和训练 loss 是同一种计算：金标的下一个 token 放在那里，看模型猜得偏不偏。五个标题它只要写得很熟，eval loss 就会降。它看不出这句话是不是越过了证据。

「没有 dump，却写已完成音素级验证」这种错，由 `src/ticket_sft/rules.py` 抓住。训练前，`build_dataset` 用它拒绝坏金标。训练后，`agent_loop` 用它检查模型自己写出来的结论。两道检查都要有。只看曲线，会漏掉这种错。

## 曲线怎么读

冒烟或正式训练之后，运行：

```text
python -m ticket_sft.plot_log --output output/sft_9b
```

或者另开终端运行 `bash scripts/board.sh`。蓝线是训练 loss，橙线是验证 loss。

可以按这个顺序看：

1. 前几个 step 上下跳。样本少的时候这是正常的，先不要停。
2. 蓝线整体往下。说明要学的 token 更可预期。
3. 蓝线往下、橙线往上。模型更会做练习册上的题，留出的单却更差。这是开始背训练集。停止继续加 epoch，换更早的 checkpoint。
4. 两条线都很高、几乎是平的。学习率可能太小，或者数据没喂进去。先看日志里的 step 是否在增加，再看 `check_data` 是否真的通过。

`SAVE_TOTAL_LIMIT=3` 会留下最近三个 checkpoint。橙线开始变坏时，用前一个目录里的适配器，不必从头训练。

## 动手

在纸上写你第一批真实数据打算怎么留验证集。至少包括：哪些车厂、哪些语种一定要在验证集里出现，以及这些单不会同时出现在训练集。写不出来，就先不要把 `NUM_TRAIN_EPOCHS` 调大。
