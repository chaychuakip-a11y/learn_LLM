# 工具调用、思考模式，以及模型改不了什么

读完这一课，你应该能把一次分析从头到尾讲成五步，并且说清哪几步发生在模型外面。

## 模型写出脚本文字，沙箱才执行

模型里面没有 Python 解释器。它生成的是文字。我们把其中一段文字的格式训练成工具调用：名字是 `run_analysis`，参数是 `code`，值是一段 Python 源码。

真正执行发生在模型外面：

1. 你把系统提示和问题单交给模型。
2. 模型写出 `tool_call`，里面是它认为该跑的脚本。
3. `agent_loop` 或线上服务把这段源码交给沙箱。
4. 沙箱只读运行，把打印出来的 JSON 收走。
5. 这段 JSON 作为新的上文交回模型，模型再写五个标题的结论。

沙箱会拒绝写文件、联网和再开子进程。这是为了让脚本只做检查。它不是一道面向公网的安全边界。模型如果写出 `open('词典','w')`，沙箱会失败，这条失败会写进工具结果，模型有机会再写一次。

训练数据里的脚本目前都是一次就写对的。失败之后再试一次的过程，还没有放进 jsonl。所以第一版模型更熟悉「直接写出能跑的脚本」，不太熟悉「看懂报错再改」。推理时虽然允许再试一次，不要指望它已经把改错练会了。

你可以先不加载模型，把这条链路走通：

```text
python -m ticket_sft.agent_loop --case data/example/cases/de_nav_002 --script data/example/gold/de_nav_002.py
```

这里的脚本是人写的金标。屏幕上先出现证据 JSON，再出现五个标题。训练完成之后，去掉 `--script`，改成 `--server`，脚本和结论才由模型生成。生成结果仍要用同一套规程检查。

## 思考模式在这套数据里是空的

Qwen3.5 默认会先写一段思考，再写给你看的答案。思考是它生成的另一段 token，同样占上下文，也可以占 loss。

我们的金标结论里没有思考段落。查证据的过程写在脚本里：脚本去对标注和 REC、去看分支分数、去看 dump 有没有做映射。如果训练时强迫它再写一段很长的思考，金标里又没有这段文字，格式会对不齐。

两个配置处理这件事：

- `ADD_NON_THINKING_PREFIX=true`：回答前面放一个空的思考块，让格式和这个模型的习惯一致。
- `LOSS_SCALE=ignore_empty_think`：这个空块不计入 loss。模型不用练习「把空白思考写得一字不差」，力气留在脚本和结论上。

你暂时不要在金标结论前面手写长篇思考。等脚本和结论都稳定了，再决定要不要把分析员的真实推理过程加进训练。

## 训练改不了测量本身

把下面三件事分开，后面就不容易对模型抱错期望。

模型可以学的，是写法。看见 `person_in_lexicon` 为 false，结论里写张三不在词典，并标明这是槽准。看见 `state_map_applied` 为 false，把音素解释留在待核实。看见正确文本在 fsa 里但不是获胜分支，写明它进了候选但输了。

模型学不会的，是一次新的测量：

- 车端引擎这次实际认出了什么。那在问题单的 REC 和分支里，已经测完了。
- 某个 state 数字对应哪个音素。映射表属于那个声学模型。案例里没有写 `state_map_applied: true`，结论里就不能写成音素已核实。
- 固定基线上，这次修改有没有改善，有没有把别的句子带回退。那是平台整包回归的结果，不是一张单的脚本能代替的。

微调让它更稳定地遵守这些界限。它不会因此多出一只耳朵去听音频。正式门禁仍然看平台上的完整回归。模型交出来的是一张单的三块：结论、待核实、以及为什么这还不能当门禁。

## 课后三问

先盖住答案，用自己的话写。写不出就回到对应的课，不要往下翻。

1. 标准输出为什么不计 loss？
2. 示例只有 3 条训练样本、3 个 epoch 时，大约几个 step？冒烟的 20 step 又表示什么？
3. eval loss 下降之后，还要做什么，才能说它会分析一张新单？

答案：

1. 标准输出是沙箱算出来的事实。把它计入 loss，模型会去背那份 JSON。我们要它学的是：看完 JSON，再写有证据的结论。见第 4 课。
2. 大约 3 个 step。因为 3 条样本凑不满梯度累积要求的 8 条，每个 epoch 结束更新一次。冒烟的 20 step 会把这 3 条反复看很多遍，只用来确认日志、显存和存盘。见第 6 课。
3. 用按车厂和语种留出的单，让模型自己跑 `agent_loop` 写脚本和结论，再用 `rules.py` 那套规程检查。曲线只说明金标更好猜了。见第 7 课和第 8 课前半。
