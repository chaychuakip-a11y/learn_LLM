# loss：看见了什么，又要学会什么

读完这一课，你应该能看着 `inspect` 的输出，指出哪些字模型只是读到了，哪些字的预测误差会拿去改权重。

## loss 是「猜偏了多少」

第 1 课说过，每个位置模型都在猜下一个 token。金标里下一个 token 是确定的。如果模型给这个正确 token 的概率很高，这一步就算猜得准。如果概率很低，正确的字排在很后面，这一步就算猜得偏。

loss 把「猜得有多偏」变成一个数。猜得越偏，loss 越大。一个 step 结束时日志里打印的 loss，是这一步里所有要计分的位置平均之后的结果。数字从 2 点几降到 1 点几，表示这些位置上的正确 token 变得更可预期。它不是百分制考试分，没有「60 分及格」这种读法。只看它是在往下降、在乱跳，还是已经贴在地板上。

反向传播是后面的计算：把这个误差送回那些可以修改的数字，告诉它们该往哪边改一点。你不需要手算。你需要知道误差从哪些字上来。算进 loss 的字，才会推动修改。没算进 loss 的字，模型仍然能看见。

## 一条样本里的两种字

`python -m ticket_sft.inspect --id zh_contact_004` 会把一条样本分成两种：

`[上下文]` 模型读，但不拿来改权重：

- `system`：岗位说明
- `user`：问题单，里面有「打电话 给 张三」和 REC
- `tool_response`：脚本打印出来的证据，比如张三不在词典里

`[要学]` 预测这些字时的误差才计入 loss：

- `tool_call`：标准脚本
- `assistant`：标准结论

用中文联系人这条走一遍。模型先读到岗位说明和问题单。然后它要写出脚本。脚本的每一个 token 都有金标，猜偏了就产生 loss。脚本写完之后，沙箱的输出作为事实放进来，这一大段 JSON 不算 loss。最后它要写出「按槽准，张三不在词典里」。结论的每一个 token 再次产生 loss。

这样分的原因很具体。证据 JSON 是程序算出来的，不是分析员「创作」出来的。如果这段也算 loss，模型会把力气花在背诵 `person_in_lexicon: false` 这串字上。我们要它学会的是：看见这串字之后，结论里写出「张三不在词典里」，并且不要写成声学已经验证。

问题单同理。那是用户交给它的。让它练习把问题单原文再打印一遍，没有分析上的意义。

## 结论里多出来的话，会被当成正确

loss 只认金标。金标结论里有一句证据 JSON 里找不到的话，模型也会把这句话当成该学的正确 token。训练越多，它越会在新单上写出这种没有证据的话。

所以写 `.md` 的时候，每一句结论都要能在脚本输出里找到对应字段。`build_dataset` 会做几条硬性检查，例如没有 dump 却写了「已完成音素级验证」就拒绝写入训练集。它查不全所有发挥。字段对得上，仍然要人看一遍。

## 改了提示，就要重新生成 jsonl

系统提示存在每一条 jsonl 里，不只存在 `prompts/system.md`。你改了 markdown，旧的 jsonl 还是旧提示。模型会按旧提示学。改完提示后重新运行：

```text
python -m ticket_sft.build_dataset
python -m ticket_sft.check_data
```

`check_data` 发现提示和当前文件不一致时会提醒。看到提醒就重新构建，不要直接开始训练。

## 动手

运行：

```text
python -m ticket_sft.basics 4
```

课的最后会打印 `zh_contact_004` 每一段的字数。请你看两眼：

- `tool_response` 往往比结论长很多。它占窗口，但不推着权重改。
- `assistant` 比问题单短。真正要学的结论，字数可以不多，但每一句都要有证据。

然后打开 `output/debug/report.html`。页面上的蓝字就是计入 loss 的部分。蓝字和黑字对上这一课的表，这一课就算过了。
