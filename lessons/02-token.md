# token、上下文和截断

读完这一课，你应该能讲清：模型吃进去的不是「一句话」，而是一串编号；为什么一条问题单写太长，结论会被悄悄裁掉。

## token 是编号，不是字

模型的输入必须是整数。分词器负责把你看到的文字切成整数，每个整数叫一个 token，对应词表里的一项。

切分规则不是「一个汉字一个 token」，也不是「空格分开就是一个词」。大致可以这样记，方便估计，但不要当真值：

- 常见中文，常常接近一个字一个 token。
- 英文和代码，往往几个字母才是一个 token。
- 泰语、阿拉伯语的切法和中文不同，同一句话的 token 数不能按汉字的经验去套。
- 标点、换行、JSON 的引号和括号，也都占 token。

所以「这条约 300 个字」不能直接说成「300 个 token」。仓库里的粗估故意算得偏大：中文、泰语、阿拉伯语按一个字一个 token，英文和符号按两个字符一个 token。偏大是为了安全。真要知道分词器怎么切，等模型下载到内网之后，用它自带的分词器量。粗估没超过上限，真值通常更短，训练时不容易被裁。

## 上下文就是这一次能看见的全部编号

模型一次能看的 token 数有上限，叫上下文长度，也叫窗口。`configs/sft_9b.env` 里的 `MAX_LENGTH=4096` 就是这次训练用的上限。

一条训练样本会把这些东西串成一条长序列：

1. 系统提示
2. 问题单 JSON
3. 脚本
4. 脚本打印出来的证据 JSON
5. 五个标题的结论

它们共用这 4096 个位置。证据 JSON 往往最长，因为里面有对齐结果、分支分数、词典检查。结论在最后面。

中文联系人那条样本，粗估大约 2700 token，还放得下。你以后把一张单写成十几句音频，再把完整 dump 贴进提示词，就可能超过 4096。

## 超长时，裁掉的是右边

训练程序不会把超长的样本折成两页。它从右边截断，留下开头的 4096 个 token。开头是系统提示和问题单，结尾才是结论。截断之后，模型学到的金标是半截结论，甚至结论整个不在了。程序不一定报错，loss 看起来也在下降，只是学的内容已经坏了。

`check_data` 和 `build_dataset` 会用粗估去比 `MAX_LENGTH`。粗估超过上限，训练集根本不会写出来。这是故意的。与其让你训一个学了半句话的模型，不如先把单写短。

单太长时有两个办法：

- 拆开。一张单里十句以上，按句子或按失败类型拆成多条样本。
- 提示词里只放摘要。原始日志留在案例目录里，让脚本用 `analysis.load_case()` 去读。模型看见的是脚本打印出来的短 JSON，而不是整份原始 dump。

## 看见，和要它学会，先分开记

窗口里的每一段，模型都能用来猜后面的字。问题单在窗口里，它就「读到了」这张单。结论也在窗口里，那是你希望它学会写出来的部分。

这两件事下一课和第 4 课会分开处理。这里先留一个印象：放进窗口，只说明它这次看得到。看得到的东西，不一定拿来改权重。

## 动手

如果还没生成数据，先在仓库根目录执行：

```text
python -m ticket_sft.build_dataset
python -m ticket_sft.inspect --id zh_contact_004
```

`inspect` 会列出每一段有多少字。对照这一课的五段顺序，指出哪一段最长。那一段通常是标准输出。它占窗口，但是第 4 课会告诉你：它不参与 loss。

然后运行 `python -m ticket_sft.basics 2`。课的最后会列出你当前每条样本的粗估 token。最长的那条离 4096 还剩多少，心里有个数。以后自己的单超过这个粗估，就先拆，再谈训练。
