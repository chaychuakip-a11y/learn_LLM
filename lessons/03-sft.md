# 预训练、指令模型，和你这次的微调

读完这一课，你应该能分清三种训练，并且知道自己这次只做第三种。很多人第一次训模型，会把「下载一个模型」和「自己训练一个模型」当成同一件事。它们不是。

## 第一种：预训练

预训练用海量普通文本，让模型练习猜下一个 token。小说、网页、代码、多种语言的句子都在里面。做完这一步，模型会把句子接得像人话，也会写简单的程序。

这一步要的数据和显卡，不是一台内网机器几天能完成的。你不需要做，也不该做。`Qwen3.5-9B` 的作者已经做完了。你下载下来的那 90 亿个数字，就是这一步加上后面指令训练的结果。

## 第二种：指令后训练

只做过预训练的模型，常常会把你的问题继续「往下编」，像在续写文章，而不是按你的格式回答。指令后训练用大量「人怎么问、助手怎么答」的对话，让它学会：

- 按你的要求组织答案
- 该停的时候停
- 遇到工具说明时，按工具的格式把参数写出来

`Qwen3.5-9B` 这个文件已经包含指令后训练。它会中文和很多其他语言，也会写 Python，也见过工具调用的样子。你选择它，就是在利用这些已经学会的能力。

仓库配置里的 `MODEL=Qwen/Qwen3.5-9B` 指的就是这份已经会听话的模型。名字里带 Base、没有做过对话训练的文件，不适合直接套我们这种 `messages` 数据。

## 第三种：你这次做的监督微调

监督微调的英文缩写是 SFT。监督的意思是：标准答案是人写好的，模型对着答案学。

一条答案在这个项目里是一整段对话，存在 `data/processed/train.jsonl`。打开它，每一行是一条样本，里面的 `messages` 有五个角色：

| 角色 | 谁写的 | 内容 |
| --- | --- | --- |
| system | 你 | 岗位说明 |
| user | 你 | 这张问题单 |
| tool_call | 分析员的标准写法 | 该跑的 Python |
| tool_response | 沙箱 | 脚本打印的证据 |
| assistant | 分析员的标准写法 | 五个标题的结论 |

微调要让模型在看到前面几段之后，把 `tool_call` 和 `assistant` 写得更像表里的标准写法。车厂规程、五个标题、没有 dump 就写待核实，都是从这些标准写法里学来的。

## 教师强制：训练时它看不到自己的错字

训练的时候，模型猜「结论的下一个字」时，前面放的是金标里的字，不是它自己刚才猜错的字。这叫教师强制。老师把正确的上一句按在桌上，学生只练习接下一字。

这样 loss 会比较好算，也会下降得比较整齐。副作用是：loss 低，只说明「答案就放在前面时，它接得更顺」。真正使用时，没有人把后半段答案先写好。它必须自己把脚本和结论从头生成。生成一旦开头偏了，后面会跟着偏。

所以训练完不能只看 loss 曲线。要用 `agent_loop` 给它一张它没见过的单，让它自己写脚本、自己写结论，再拿规程去检查。

## 强化学习先不做

还有一种训练叫强化学习。它不给整段标准答案，只给一个分数。比如规程检查通过加分，乱写「声学已验证」扣分，模型自己多试几种写法，朝高分的写法改。

这需要你先有稳定的打分规则，也更吃显卡。当前仓库只做 SFT。`rules.py` 里的检查先用来过滤训练数据和检查生成结果。等标准答案写稳了，再考虑要不要用这些规则当奖励。

## 动手

用编辑器打开 `data/processed/train.jsonl` 的第一行。不用读懂每一个字段。只要找出这五个角色的名字：`system`、`user`、`tool_call`、`tool_response`、`assistant`。

然后问自己：如果把 `assistant` 里的结论删掉，模型还学得会写结论吗？学不会。SFT 学的就是这些已经写好的字。没有金标结论，就没有可学的结论。
